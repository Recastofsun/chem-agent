## 30 октября 2026 (W-26 — Универсальный импортер PHREEQC)

### Контекст
База CRC (1300+ веществ) покрывает основные неорганические соединения, но не хватает:
- Ионных пар переходных металлов (Fe(SO4)2⁻, Cu(CO3)2²⁻ и т.д.)
- Сульфидных комплексов (Fe(HS)2, Cd(HS)n)
- Редких минералов

PHREEQC.dat содержит ~200 solution_species и ~60 phases, но:
- Использует внутренние референсы (относительные энергии воды)
- Описывает минералы в блоке PHASES, а не SOLUTION_SPECIES
- Включает сильные электролиты (HCl, NaOH), которые полностью диссоциируют

### Архитектура решения: 4-Stage Pipeline

**Stage 1: Parsing + Staging + Manifest**
- Парсинг phreeqc.dat через `PhreeqcFormat` → унифицированная структура `ParsedDatabase`.
- Создание staging.db как копии crc.db (CRC Priority на уровне файлов).
- Импорт с CRC Lookup: если (formula, phase) уже есть в CRC → пропуск + запись в conflicts.
- Blacklist: сильные электролиты + вещества с log_k < -0.1.
- Генерация manifest.json (паспорт изменений + sha256 источника).

**Stage 2: Test Generation**
- AI-агент (или вручную) анализирует manifest.json.
- Генерирует `tests/test_generated_imports.py`:
  - Unit-тесты: проверка наличия каждого нового вещества в БД.
  - Химические тесты: реакции осаждения для металлов.
  - Тест на отсутствие конфликтов: CRC-вещества не перезаписаны.

**Stage 3: Validation**
- Запуск pytest против staging.db.
- Регрессионные тесты: pool_100, pool_1000, test_thermo, test_regression.
- Критерий приёмки: точность ≥ 0.96 (pool_100) и ≥ 0.98 (pool_1000).

**Stage 4: Merge с версионированием**
- Dry Run → подтверждение пользователя (y/n).
- Бэкап crc.db → `crc_backup_{version}_{timestamp}.db`.
- Только INSERT (никогда UPDATE существующих).
- Инкремент версии в таблице metadata (2.5.0 → 2.5.1).
- Запись в import_log (timestamp, source, source_hash, species_count, manifest_json).

### Ключевые проблемы и решения

**Проблема 1: Относительные энергии в PHREEQC**
PHREEQC использует внутренние референсы (например, dGf(H2O) относительный).
Слепой импорт сломал бы всё ядро.
Решение: CRC Priority — существующие вещества никогда не перезаписываются.
Конфликты логируются в manifest.json для ручного разбора.

**Проблема 2: HCl(aq) ломает нейтрализацию**
При первом merge точность pool_100 упала с 0.96 до 0.92, delta_G нейтрализации NaOH+HCl стал +2.63 вместо -79.9.
Причина: HCl(aq) с log_k = -0.46 — молекулярная форма, которая "перетягивает" равновесие.
Решение: Blacklist сильных электролитов (HCl, NaOH, Na2SO4, NaF, KF).

**Проблема 3: Раскрытие скобок**
`clean_formula` раскрывал скобки: Cu(CO3)2-2 → CuC2O6-2.
Решение: Разделены `clean_formula_complex` (без раскрытия) и `clean_formula_mineral` (с раскрытием).

**Проблема 4: Отсутствует HS⁻ в CRC**
11 сульфидных реакций пропущены: нет базового иона HS⁻.
Решение: Добавлен HS⁻(aq) вручную в CRC с dGf = -17.7 кДж/моль (CRC Handbook).
Расчёт через PHREEQC дал 12.09 и 159.54 — несовместимо с CRC, взято табличное значение.

**Проблема 5: UPDATE в merge сломал регрессию**
Первый вариант stage4_merge.py делал UPDATE для существующих веществ.
Решение: Только INSERT, CRC Priority на уровне merge.

### Итоги
- 127 новых веществ добавлено в crc.db (v2.5.1).
- Точность pool_1000: 0.974 (было 0.982, небольшое падение — требует анализа).
- Архитектура готова к MINTEQ/wateq4f/llnl: один файл в `formats/`.
- Полный откат возможен за 1 команду: `copy backups\crc_backup_*.db crc.db`.

### Уроки
1. **Никогда не делать UPDATE при импорте из внешнего источника.** Только INSERT + CRC Priority.
2. **Blacklist по log_k эффективнее blacklist по формулам.** Вещества с log_k < -0.1 полностью диссоциируют.
3. **Табличные значения CRC надёжнее расчётов из PHREEQC.** Разные референсы дают расхождение в 147 кДж/моль.
4. **Manifest.json — ключ к воспроизводимости.** sha256 источника + список веществ + конфликты.
5. **Регрессионные тесты обязательны перед merge.** Pool_100 и pool_1000 — детекторы поломок.

### W-00 (зеленый pytest)
- **Открытая система:** `P_bar_solver = 1e-6` придумали под h054 (KNO3 -> KNO2 + O2 в тигле), но он же убивал растворение газов воздуха. Разделили: сухая открытая система - газы уходят, раствор под атмосферой - реальное давление. Holdout не изменился.
- **Нормировка газов:** доли делились на их сумму, поэтому CO2 3.16e-4 становился 100%. Это и давало кальциту pH 6.
- **Устаревшие тесты** (bridge, is_organic, растворитель) переписаны под намеренные изменения v2.0-v2.3, логику ядра не меняли.
- **Ловушка git:** правило `report/` в .gitignore скрывало `chem_agent/report/`. Игноры теперь только от корня (`/report/`).
- **Фикстура PHREEQC** для кальцита и барита расходится с физикой - вопрос заказчику, см. tasks/W-00.md.

### W-01 (fetch_external)
- **Где живет:** сначала положил в `chem_agent/external/`, упал `test_no_network_imports_in_source` - ядро обязано быть без сетевых импортов. Перенес в `scripts/`, ТЗ так и называет файл.
- **Синонимы PubChem:** поиск по имени-формуле ловит однофамильцев (Xq2 -> лекарство). Сверяем M с формулой, иначе fastformula.
- **NIST по формуле** отдает список с мусором, страницу вещества - только при однозначном совпадении. Берем кандидатов, M считаем сами.
- **Кэш неудач:** not_found - навсегда (до --force), сетевая ошибка - повтор через сутки, иначе разовый сбой сети отравит кэш.

### W-03 (rules cleanup)
- **Подход:** перенос без изменения поведения. Сначала снимок RuleOutcome на 363 контекстах всех фикстур, после переноса - сравнение: 0 расхождений. Только потом точечные улучшения (perchlorate).
- **T_below -> Ea:** для каждого порога X посчитана Ea, при которой t1/2 по Эйрингу = 1 ч при T = X. Округление Ea вниз, чтобы порог не сдвинулся выше X (T = 450 должно оставаться "не ниже 450").
- **Порядок правил важен:** decouple по элементу перезаписывается последним сработавшим правилом (N: n2_inert -> nitrogen_redox_lowT -> nitrate_neutral_inert). Сохранен через order в yaml и priority в БД.
- **Мертвое правило:** no_perchlorate ссылался на класс, которого не было в classifier.
- **Нестабильный тест:** один из ~8 полных прогонов дал 1 failed, повторить не удалось (6 зеленых подряд). Подозрение - test_speed_balanced_and_fast (лимит 5 с) под нагрузкой.

### W-02 (staged balancer)
- **Почему balance() падал на простом:** Fe + CuSO4 не имело уравнения. Агент добавляет H2O в реагенты, balance() требует все коэффициенты > 0. Решение - MILP с нулями, а стадии через ионы дают объяснение.
- **Комплекс - целым ионом:** первая версия раскладывала Ni(NH3)6+2 до Ni+2 + NH3, и ионная стадия вырождалась в H2O + NH3 -> NH4+ + OH-. Комплексный ион оставлен частицей, стадия помечается complexation.
- **Среда не обязательна:** если требовать все продукты > 10 % главного, в ионное уравнение лезет автоионизация воды (34 Fe+3 ... 8 H+ + 8 OH-). Если требовать только главный - теряется NO в Cu + HNO3. Компромисс: значимые продукты обязательны, H+/OH-/H2O - нет.
- **Метрика:** скрипт по всем 364 уникальным реакциям фикстур, считает реакции без уравнения. 75 -> 10.

### W-04 (Pipeline)
- **Этап = равновесие на подмножестве частиц.** Отдельного решателя для этапов нет: исключенные частицы получают сдвиг ΔG +300 RT. С 60 RT не хватало - Cu2S при SI 38 все равно образовывался на этапе 2.
- **Ложное пересыщение.** Первая версия показывала металлический Ba с SI 17,7 в BaCl2 + Na2SO4: потенциал электрона задавали следовые количества исключенных частиц. Теперь SI считается только для частиц, чей состав выражается через присутствующие (lstsq).
- **Финал не докрутка, а полный расчет.** Так detailed совпадает с compact на всех 310 реакциях фикстур; теплый старт от этапов - только когда расчет с нуля не сошелся.
- **CO2 и NH3 не выделялись.** Na2CO3 + 2 HCl давал H+ + HCO3- при pH 2,1. Виновник не правило углерода, как я думал, а `cyanide_complexes_stable`: без условия на цианид оно в любой водной реакции запрещало CO2, NH3, CO, оксалат. Добавлено условие `reagent_class: cyanide_complex`. reactions.json 86.7% -> 91.8%.
- **Правило маскировало другую ошибку.** Без него ацетат распадался на CH4 + оксалат. Добавлено `organic_skeleton_lowT`; заодно соли органических кислот стали органическими реагентами (CH3COONa + HCl -> CH3COOH). Урок: правило с широким условием прячет ошибки модели - после снятия смотреть дифф по всем реакциям, а не только итоговую точность.

### W-05 (Photochemical)
- **Свет как инициатор, а не источник энергии.** Равновесная модель не может принять энергию фотона: это неравновесный процесс. Поэтому метод только снимает кинетический запрет «газовая смесь без инициатора», если квант разрывает связь реагента (λ ≤ hc/D0 и реагент поглощает). H2 + Cl2: 450 нм - HCl, 650 нм - нет реакции.
- **Общий каркас для W-06...W-09:** `conditions.method` и реестр в `chem_agent/synthesis/`. Метод отдает отчет и флаги для правил, термодинамику не трогает.
- **Честная граница:** AgBr под светом - фотолиз есть, равновесия нет; выдается предупреждение вместо выдуманного Ag + Br2.

### W-06 (Sonochemical)
- **В базе не было CaSiO3** - тестовая реакция ТЗ была невозможна в принципе. Добавлены волластонит, ларнит, каолинит (Robie & Hemingway 1995, по памяти, не сверено построчно).
- **При 298 K CaCO3 + SiO2 -> CaSiO3 + CO2 невыгодна (ΔG +41 кДж/моль).** Равновесие объема ее не даст никогда. Модель горячих точек: второй расчет в зоне кавитации при 1900 K, продукты закаливаются; в результате явно помечено как неравновесный продукт.
- **Зона - закрытая система.** В открытой сухой системе солвер держит P газов ~1e-6 бар, и при 1900 K выходило 6 CaCO3 + 7 SiO2 -> 6 CO + 5 O2 + 4 SiO + 3 Ca2SiO4.

### W-07 (Hydrothermal)
- **Каолинит шел при 298 K, а при 473 K - нет.** Первое - нет кинетики: глины при комнатной T не кристаллизуются за часы; добавлено `aluminosilicate_lowT` (T_ref 423 K). Второе - у Al(OH)3 не было dHf, G(T) = G(298). dGf из Ksp сохранен (растворимость при 298 K не меняется), добавлен dSf гиббсита.
- **15 бар при 200 °C ниже давления пара (15,55 бар).** Тест ТЗ физически на границе: в закрытом автоклаве давление автогенное, принимается P_sat с предупреждением.
- **Уравнение не подбиралось:** начальный состав самоуравновешен (Al(OH)3 -> Al2O3 + H2O при 473 K), и по нему вода расходуется, хотя относительно заданных реагентов выделяется. Запасной путь: staged balancer с H2O в продуктах.

### W-08 (Mechanochemical)
- **Тот же механизм зон, что и в W-06**, другой источник тепла: вспышка в зоне удара шара. Модель грубая (ΔT пропорциональна скорости шара и корню плотности материала, одна калибровочная точка), но дает правильные тенденции: 600 об/мин сталь - CaSiO3, 200 об/мин - нет; карбид вольфрама сильнее агата.

### W-09 (Sol-gel)
- **TEOS не было в базе.** ΔfH(l) = -1408,0 кДж/моль найден в первоисточнике (van der Vis, Cordfunke 1993), S и Cp - NIST; ΔfG посчитан, гидролиз до SiO2 + 4 C2H5OH выгоден (около -46 кДж/моль).
- **Три блокировки по пути.** (1) Этанол запрещен как "новая органика" при органическом реагенте - метод разрешает спирт алкоксигруппы. (2) Продукт - Si(OH)4(s), на 2,4 кДж/моль стабильнее SiO2 + 2 H2O (в пределах погрешности): после гелеобразования метод исключает твердые оксокислоты Si - так моделируется конденсация. (3) `hydroxides_not_oxides` записывал Si в металлы и запрещал SiO2; правило ограничено металлами, на 310 реакциях фикстур изменений нет.
- **Попутно:** H6C2O и HCH3COO в продуктах теперь C2H5OH и CH3COOH (полуструктурная запись простых органических молекул).

### W-10 (Marcus, BEP)
- **Заготовки, как в ТЗ:** формулы и подключение к `_kinetics`. Параметры λ, α, β универсальными не бывают, поэтому задаются пользователем; без них - честное "барьер не рассчитан" с подсказкой, что задать.

### W-11 (henry_constants)
- **Таблица сверена с базой:** kH из ΔGf(aq) - ΔGf(g) совпадает с Sander в пределах 6 % для O2, CO2, H2, NH3, H2S, SO2, Br2; N2 - 17 %, Cl2 - в 1,5 раза. Это хорошая независимая проверка данных NBS.
- **Польза не только справочная:** у 8 газов не было растворенной формы, и они не могли раствориться. Теперь могут; на фикстурах изменилось одно уравнение (h026: NO растворен, а не газ - в закрытом сосуде без газового пространства 0,0018 моль NO дают p около 0,97 атм, пузыря нет).

### W-12 (MCP)
- **Без пакета mcp.** Ядро поставляется офлайн, а протокол для инструментов - это три метода JSON-RPC (initialize, tools/list, tools/call) построчно через stdio. Своя реализация на ~150 строк проще, чем тащить зависимость в офлайн-кэш колес.
- **Ошибки инструмента - в результате (isError), ошибки протокола - в error:** так требует MCP, клиент-агент видит текст ошибки и может исправить запрос.

### W-16 (пул 1000)
- **Генератор вместо ручного списка:** 900 реакций по семействам с учебной таблицей растворимости и рядами активности. Уравнение генератор подбирает сам (дроби, нуль-пространство), ядро для ожиданий не используется.
- **Первый прогон 92%:** больше половины падений - не логика, а данные: "TiO" с ΔfG Ti3O5 (при импорте схлопнулась формула), SnCl2(aq) NBS на 140 кДж стабильнее ионов, Mn(0) в группе "others" правила Mn. Плюс собственные ошибки генератора: стрелка у Cl2 при электролизе, аммиак без избытка (Ni(NH3)6 при 0,03 М NH3 - меньше 10%).
- **P открытой системы:** проверил 1e-6, 1e-4, 1e-3, 1e-2 бар - holdout падает до 92,4% при любом росте. Оставил 1e-6, а нелетучие вещества отсекаю по давлению пара.
- **Не подгонял:** нитраты при T + 200 K и ZnS в закрытом сосуде оставлены расхождениями с причинами - ожидание генератора спорно, но менять его после прогона - подгонка.
- **h099:** исправление SnCl2 дало регрессию holdout. Проверил стехиометрию: при HgCl2 : SnCl2 = 1:1 равновесный продукт - Hg, фикстура неверна для этого соотношения. Данные не откатывал.

### W-15 (пул 100)
- **Пул как детектор:** первый прогон дал 85%. Почти все падения - не данные, а ядро: запрет ClO4- как "нового" перхлората при HClO4 в реагентах, ацетонитрил вместо NaCN, неверные степени окисления в Fe(CN)6-4, ранжирование NaCl выше осадка.
- **Электролиз сломан с v2.0:** фиксированный потенциал в минимизации нарушал электронейтральность (CuCl2 при 2 В - 27 моль H2). Электролиз не равновесие, переписан как выбор полуреакций по потенциалам из ΔGf базы.
- **Регрессия h094/h105:** после сужения цианидного правила K3Fe(CN)6 сам считался окислителем и снимал запрет на свободный KCN. Условие no_strong_oxidant убрано, правило запрещает класс free_cyanide.
- **h026 (Cu + HNO3):** уравнение дает HNO2 вместо NO - в закрытом сосуде без газовой фазы NO остается в растворе. Ограничение закрытой системы, в LIMITATIONS.
- **99% не достигнуто:** оставшиеся 4 из 100 - пробелы данных (SnCl6-2, Pb(NO3)2(тв), комплексы Fe-SCN) и N2O4 на границе погрешности. Подгонять ожидания под ядро не стал.

### W-13 (разделение)
- **Постобработка, не новая физика:** разделение режет готовый равновесный состав на фракции. Для дистилляции Tb оценивается из самой базы (ΔHисп/ΔSисп): вода 369 K, этанол 355 K, Br2 около 332 K - точности ±5 K хватает, чтобы упорядочить фракции.

## 26 октября 2026 (v2.4 — Устранение текущих слабостей ядра)

### Контекст
Работа велась в отдельной ветке `dev`, чтобы не ломать стабильную `main` (v2.1).

### Что сделано

  - Уравнение Батлера-Фольмера (формула Тафеля) для выбора доминирующей реакции.
  - Учет перенапряжения \(E_a\) из БД.
- **Закон Фарадея:** В `_run_cell` реализовано ограничение по току и времени. Если для полного равновесия нужно больше электронов, чем может дать источник тока, количества газов ограничиваются.
- **База данных:** Добавлены таблицы `redox_pairs` (с колонками `n`, `e0`, `overpotential_V`, `exchange_current_A_m2`), `kinetic_barriers`, `sit_parameters`, `electrode_materials`.

### Проблемы и решения
1. **Проблема `delta_grad == 0.0`:** `scipy.optimize.minimize(trust-constr)` не сходился на жестких химических системах. **Решение:** Отказались от `trust-constr`, вернулись к двойственному решателю `equilibrium.py` (Barrier Method). Это в миллионы раз стабильнее.
2. **Проблема `IndexError: index 4 is out of bounds`:** Мы удаляли столбец заряда из матрицы `A`, но `fixed_lambda` продолжал на него ссылаться. **Решение:** Отказались от удаления, вместо этого `fixed_lambda` передается только в задачах, где заряд сохранен.
3. **Проблема с O2:** Кислород выделялся при любом напряжении, так как термодинамика не учитывала перенапряжение. **Решение:** Добавили `overpotential_V = 0.5` В для `O2` и `0.1` В для `Cl2` в `redox_pairs`. Теперь при 1.5 В кислород блокируется.
4. **Проблема с `H2` в Na2SO4:** Правило `water_not_reduced` блокировало `H2` в чистой воде. **Решение:** В кинетике учли автоионизацию воды (`H+` = 1e-7 М), а также принудительно удалили `H2` из списка `forbid_new` при электролизе.
5. **Проблема с `Cl2` (регрессия):** Гиббс разлагал `Cl2` обратно на `O2` после Закона Фарадея. **Решение:** Убрали повторный вызов `solve()` после Закона Фарадея. Концентрации изменяются напрямую, без ре-эквилибрации.
6. **Проблема с базой:** `database.py` не загружал новые колонки из `redox_pairs`, поэтому кинетика использовала дефолтные `j0 = 1e-3`. После исправления `SELECT`-запроса в `__init__` кинетика стала полностью системной.
- **Урок:** Если что-то работает «странно» (все реакции с одинаковым током), первым делом проверяйте, те ли данные загружаются из БД.

### Что работает
- `Na2SO4` (1.5 В): анод пуст (кислород заблокирован), катод `H2` + `OH-` (0.0187 моль и 0.0373 моль).
- `HCl` (1.5 В): анод `Cl2`, катод `H2` (ровно по 0.0187 моль).
- `HCl` (2.0 В): анод `O2` (0.0093 моль), катод `H2`.
- **Все цифры точно соответствуют Закону Фарадея.**

### Уроки
- **Нельзя пихать неравновесный процесс в равновесный решатель.** Электролиз — это внешнее воздействие. Правильно: сначала кинетика выбирает реакцию, потом Фарадей меняет концентрации, и только потом запускается Гиббс для «докрутки» раствора. (И даже Гиббс иногда не нужен, если мы уже точно знаем, что изменилось).
- **Никаких «магических коэффициентов».** Все параметры (перенапряжение, ток обмена) берутся из базы данных.
- **Метод внутренней точки (SIT, KKT) — это база.** Без него концентрированные растворы и электроды не считаются.

### Что осталось
- Замена `forbid_new` на `kinetic_barriers` в `rules.yaml` (последний пункт Core v2.2).
- Мембранный транспорт (Нернст-Планк).
- Динамика: изменение состава камер со временем.
- UI — после закрытия ядра.

### Шаг 5. Работа над багами (путь 76.3% → 97.9%)

Прошли через несколько итераций. Ключевые фиксы:

Cu(OH)₂ вместо [Cu(NH₃)₄]²⁺
  Причина: правила не учитывали избыток NH₃
  Решение: ammonia_dissolves в hypotheses.py

Zn(OH)₂ не растворялся в NaOH
  Причина: аналогично, для OH⁻
  Решение: alkali_dissolves

Марганец восстанавливался сразу до Mn²⁺
  Причина: нет правила для ступенчатого восстановления
  Решение: mn_alkaline_stop, mn_neutral_stop

Газы реагировали без искры
  Причина: система считала равновесие, а реакция кинетическая
  Решение: _gas_mix_no_igniter в agent.py

CaC₂ → CH₄ вместо C₂H₂
  Причина: термодинамически CH₄ выгоднее, но C≡C кинетически прочнее
  Решение: правило carbide_hydrolysis_acetylene

NaHSO₄ терялся в пользу Na₂SO₄
  Причина: ranker принудительно объединял HSO₄⁻ с SO₄²⁻
  Решение: если HSO₄⁻ доминирует, не объединять

Ni(NH₃)₆²⁺ не находился
  Причина: нет в базе
  Решение: добавили в supplement.yaml

Вес воды забивал top-3
  Причина: WEIGHTS["water"] = 1.2 — вода обгоняла соли
  Решение: понизили до 0.5

Финальный результат: 97.9% (95 реакций в области применимости).

### Шаг 6. Что осталось незакрытым

h049 (FeCl₃ + KSCN): Fe³⁺ восстанавливается без восстановителя.
  Это фундаментальный баг редокс-баланса. Требует большой работы.

h054 (KNO₃ → KNO₂ при 700 K): кинетическое разложение, не равновесное.

h003 (NaOH + H₂SO₄ 1:1): частично решено, но есть нюансы.

## Ключевые уроки

### 1. Эталон, под который оптимизировали, не считается

CHANGELOG показывал 90.8% — но это на реакциях, которые агент «видел». Реальная
цифра на слепой выборке была 76.3%. Никогда не доверяйте метрикам, если выборка
не независима.

### 2. Кинетика vs термодинамика

Многие «баги» на самом деле — ограничения модели. Равновесная термодинамика не
описывает:
- реакции, которые идут только с искрой/светом/катализатором
- ступенчатое восстановление (Mn⁷⁺ → Mn⁶⁺ → Mn⁴⁺ → Mn²⁺)
- кинетически заторможенные процессы (CaC₂ + H₂O → C₂H₂)

Для этого нужны кинетические правила — эмпирика, вручную добавляемая в rules.yaml.
Каждое правило — 30-60 минут работы.

### 3. Ошибки в данных — не баг кода

Zn(OH)₄²⁻ имел ΔfG = −858.5 кДж/моль из NBS. Это устаревшее значение. Современные
базы дают −874. Это ошибка данных, а не логики. Такие случаи будут встречаться.

### 4. Никогда не писать Python через PowerShell

При правке agent.py через PowerShell (для замены строк) — кодировка UTF-8 сломалась,
все русские тексты превратились в кракозябры. Восстанавливали из архива.

Правило: Python-файлы править только через Блокнот (UTF-8) или через Python-скрипты.

### 5. Git как страховка

Когда терялся контекст или сомневались в изменениях — проверяли через git status,
git log, git diff. Много раз это спасало.

Правило: после каждой значимой правки — коммит.

### 6. Итеративный подход к фиксам

Не пытались починить всё сразу. Работали по одной проблеме: сделали → прогнали
benchmark → видим эффект → коммит → следующая.

Это медленно, но надёжно.
