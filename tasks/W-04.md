# W-04: Pipeline (5 этапов)

## Цель
Равновесие по этапам: диссоциация -> комплексообразование -> осаждение -> газовыделение -> финал.
Ранний выход, тупик (другой порядок, fallback), режимы compact и detailed (ТЗ п. 3).

## Что сделано
chem_agent/pipeline/stages.py, orchestrator.py (новые):
1. Этап - равновесие Гиббса на подмножестве частиц. Подмножества вложены:
   1 - исходные частицы + ионы реагентов + H+/OH-/H2O; 2 - + все частицы раствора; 3 - + твердые фазы;
   4 - + газы; 5 - полный расчет без ограничений. Частица вне этапа исключается сдвигом ΔG на +300 RT
   (матрица системы и баланс масс не меняются).
2. Условия этапов: 3 - есть твердая фаза с SI > 0, 4 - равновесное парциальное давление газа выше P.
   SI оценивается только для частиц, состав которых выражается через присутствующие на этапе частицы:
   иначе потенциал задают исключенные частицы, и SI ложный (металлический Ba из BaCl2 + Na2SO4: SI 17,7).
   Пересыщение не оценить - этап выполняется.
3. Ранний выход: после этапа 1 все реагенты израсходованы (номинальная частица < 0,1 %) -> этап 5.
4. Тупик: этап 3 не сошелся -> порядок 1-2-4-3-5. Полный расчет не сошелся -> повтор с теплого
   старта от последнего сошедшегося этапа (fallback "warm_restart"). Равновесия нет -> status unknown.
5. Режимы (options.pipeline_mode, валидатор):
   - compact (по умолчанию): один полный расчет, как до W-04; этапы считаются только при несходимости;
   - detailed: этапы 1-4 всегда, шаги "Pipeline, этап N" в explanation, стадии уравнения от staged balancer.
   result["pipeline"]: mode, order, early_exit, fallback, stages (status, formed, supersaturated, невязка).

## Отклонения от ТЗ
- "Fallback на staged balancer" трактуется так: при найденном равновесии уравнение подбирает
  staged balancer (W-02, уже в _equations). Без равновесия уравнения нет - status unknown.
- Этап 5 - полный расчет с нуля, а не докрутка от этапа 4: так итог detailed совпадает с compact
  побитово. Теплый старт от этапов используется только как fallback.
- Раньше несходимость давала status error, теперь сначала fallback, затем unknown.

## Найдено попутно и исправлено: CO2 и NH3 не выделялись
Na2CO3 + 2 HCl давал H+ 0,01 + HCO3- 0,01 при pH 2,1 вместо CO2; NH4Cl + NaOH - "нет реакции".
Причина: правило cyanide_complexes_stable ("гексацианоферраты инертны") не проверяло наличие цианида
и в любой водной реакции без сильного окислителя запрещало новые NH3, HCN, CN-, C2O4-2, CO2, CO.
Ошибка из v2.4 (там же было условие только aqueous + T_below 400).
1. Условие правила: reagent_class cyanide_complex (classifier.is_cyanide_complex: C = N, без O/S/H,
   металл-комплексообразователь; KCN, HCN - не комплекс). Через scripts/patch_db_w03_rules.py.
2. Правило маскировало распад органики: после исправления CH3COOH + NaOH давал CH4 и оксалат (5 %).
   Новое кинетическое правило organic_skeleton_lowT (scripts/patch_db_organic_skeleton.py): при
   органическом реагенте ниже ~600 K не образуются неорганические частицы углерода не в степени +4
   (класс carbon_fragment). Ea 193,12 кДж/моль, как у no_new_carbon_lowT.
3. RuleContext.is_organic видит соли органических кислот (CH3COONa); раньше из-за металла - нет,
   и organic_no_new запрещал CH3COOH в CH3COONa + HCl (hydro-001).
Итог: reactions.json 86,7% -> 91,8%, holdout 95,2% без изменений. Из 310 реакций изменились 18:
12 исправлены (gas-001...005, gas-013...015, hydro-001, hydro-004/005, h019), prec-032 без изменений по сути,
5 органических (organic-001/002/004/009/010) были неверны и остались неверны с другим побочным продуктом
или "нет реакции" вместо CH4 + CO. Главный продукт Ag в organic-010 сохранился.
tests/test_rules_w03.py: +6 тестов. Попутно: test_rate_limiter_spacing мигал на Windows (шаг monotonic
~15 мс при интервале 20 мс) - переведен на perf_counter и интервал 50 мс.
