# W-02: staged_balancer.py

## Цель
Если balance() вернул None - разбить уравнение на элементарные стадии через промежуточные частицы,
сбалансировать стадии, просуммировать; не сходится - None (ТЗ п. 4).

## Причина отказов balance()
Требует строго положительный коэффициент у каждого участника. Агент добавляет H2O в реагенты
(вода слегка расходуется на гидролиз) - Fe + CuSO4 + H2O -> Cu + FeSO4 решается только с нулем у воды.
То же с побочными H+, OH-, HNO2 и т. п.

## Что сделано
chem_agent/search/staged_balancer.py:
1. Промежуточные частицы: соли и ионные пары -> ионы (naming.salt_decomposition), комплексный ион
   остается целым; комплексы (complex_constants) и гидроксо-формы M(OH)n распознаются, decompose(deep=True)
   разбирает их на металл и лиганды.
2. Коэффициенты: минимальное целочисленное решение баланса элементов и заряда (scipy milp, коэффициенты
   0..60, лимит 2 с). Главный продукт >= 1, значимые продукты (>= 10 % главного) обязательны, кроме среды
   (H+, OH-, H2O). Не нашлось - только главный.
3. Стадии: диссоциация реагентов -> ионная (или complexation, если образуется комплекс/гидроксо-форма)
   -> ассоциация продуктов. Зрители сокращаются. Сумма стадий проверяется по элементам и заряду.
agent.py: staged_balance - запасной путь для молекулярного уравнения (после всех попыток balance)
и для ионного. В balanced_equations добавлены "balancer": direct | staged и "stages".

## Ограничения
- lg beta из complex_constants используются только для распознавания комплексов, численно - нет:
  какой комплекс образуется, решает равновесие (W-04 Pipeline).
- Уравнение отражает равновесный состав: где он кривой (FeCl3 + KSCN, h049), уравнение тоже.
